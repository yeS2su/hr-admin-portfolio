첫날 OT를 보완하는 온보딩 자료

노션 페이지 / 의견 반영

추진 배경

인수인계받은 OT 자료로 약 10분간 OT를 진행해 왔습니다. 자료가 회사 소개와 제도 요약 위주로 구성되어 장비 세팅, 그룹웨어 사용법 등 입사 첫날 필요한 내용은 다루지 않았고, 입사 이후에도 유사한 문의가 반복되었습니다. 이에 입사자가 다시 확인할 수 있는 자료가 필요하다고 판단했습니다.

수행 내용

입사자에게 반복해서 받은 문의를 주제별로 분류해 수록 내용과 안내 순서를 정했습니다. 기존 업무와 병행하기 위해 내용을 먼저 정리한 뒤, Claude와 Notion을 연동해 페이지를 제작했습니다.

확인 사항입사 첫날 체크리스트와 수습기간 안내를 구분하고, 제도별 안내를 각 페이지에 정리했습니다. FAQ와 익명 건의 창구를 마련해 입사자 의견을 반영할 수 있도록 했습니다.

BEFORE

인수인계받은 OT 자료로 진행하던 약 10분간의 OT

  1. 입사 첫날 담당자가 OT 자료(PPT 29장)를 읽으며 약 10분 내 안내
  2. 회사 개요, 조직도, 직급 체계, 연차, 급여, 근태, 복리후생 7개 항목 설명
  3. 근로계약서와 그룹웨어 계정은 OT 이후 문자로 별도 안내
  4. 이후 궁금한 사항은 입사자가 담당자에게 개별 문의

개선 필요 사항OT 자료가 회사 소개와 제도 요약 위주로 구성되어, 장비 세팅, 그룹웨어 사용법, 휴가·근로 신청 절차, 수습기간 안내는 포함되어 있지 않았습니다. 입사자가 다시 확인할 수 있는 자료가 정리되어 있지 않아, 같은 내용도 매번 담당자를 통해 확인해야 했습니다.

입사자가 필요할 때 직접 확인하는 온보딩 페이지

  1. 입사 첫날 ‘시작하기’ 체크리스트에 따라 서류, 계정, 사진 제출, 인사 순으로 진행
  2. 궁금한 제도는 메인 페이지의 ‘빠르게 찾기’를 통해 해당 페이지에서 확인
  3. 해결되지 않은 문의는 FAQ·피드백 창구로 접수해 페이지에 반영

개선 내용OT에서 충분히 안내하지 못한 내용을 입사자가 첫날 이후에도 다시 확인할 수 있게 되었습니다. 반복되던 문의의 답변을 페이지에 정리해, 동일한 문의에는 해당 페이지를 안내하고 있습니다.

메인 페이지 · 회사 로비 사진을 커버로 사용하고, 상황별 ‘빠르게 찾기’를 상단에 배치

  • 경조휴가·경조금 지급 기준표, 회사·상조회 지원 정리표

구성 시 고려 사항

  • 상황별 바로가기입사자가 상황에 맞는 페이지로 바로 이동할 수 있도록 메인 페이지 상단에 ‘첫날 할 일 → 시작하기’ 형식의 빠른 찾기를 배치했습니다.
  • 첫날 진행 순서에 맞춘 체크리스트서류·계약 → 계정·시스템 → 사진·처우 → 인사·적응 순으로 구성해, 체크리스트에 따라 첫날 절차를 누락 없이 진행할 수 있도록 했습니다.
  • 가독성을 고려한 구성분량이 많은 제도 안내는 토글로 접고, 반드시 확인해야 할 내용은 색상 콜아웃으로 강조했습니다.
  • 익명 건의 창구 마련입사 초기에는 담당자에게 직접 문의하기 어려운 사항도 있다고 판단해, FAQ와 함께 익명 건의 창구를 마련했습니다. 접수된 의견은 페이지에 반영해 보완하도록 했습니다.

임직원 주차할인 자동등록 웹앱

주차할인은 업체 관리자 계정으로 로그인해야만 등록할 수 있어, 임직원이 요청할 때마다 담당자가 대신 등록해 왔습니다. 업체 시스템이 내부적으로 사용하는 API를 확인해 연결하고, 임직원이 개인 코드와 차량번호만 입력하면 로그인 없이 직접 등록하도록 웹앱을 만들었습니다. 코드 작성은 Claude와 함께 진행했고, 차량 조회와 할인 적용이 실제로 동작하는지 확인했습니다.

추진 배경

할인 등록에 관리자 계정이 필요해 담당자가 요청을 받아 대신 처리했습니다. 관리자 계정에는 유료 할인과 크레딧 관련 기능도 있었습니다.

수행 내용

직접 등록하는 흐름과 개인 코드 방식, 할인 항목을 정했습니다. AI와 코드를 작성하고 차량 조회와 할인 적용 동작을 확인했습니다.

확인 사항무료 할인 2종만 적용하고 개인 코드 확인과 사용 중지를 반영했습니다. 본인 차량 대조, 사용 기록과 횟수 제한은 검토 중입니다.

담당자가 업체 콘솔에 로그인해 대신 등록

  1. 임직원이 담당자에게 차량번호와 함께 할인 요청
  2. 담당자가 업체 관리자 계정으로 콘솔에 로그인
  3. 차량번호 4자리로 입차 차량 조회
  4. 할인 항목 2종을 하나씩 선택해 적용

직접 등록할 수 없었던 이유할인 등록은 회사에 발급된 업체 관리자 계정으로만 가능합니다. 이 계정으로는 크레딧 충전과 유료 할인까지 다룰 수 있어 임직원에게 공유할 수 없었고, 모든 요청이 담당자를 거쳐야 했습니다.

임직원이 로그인 없이 직접 등록

  1. 개인 코드와 차량번호 뒤 4자리 입력
  2. ‘할인 등록’ 버튼 클릭
  3. 조회부터 할인 2종 적용까지 자동 처리, 결과를 화면에 바로 안내

달라진 점업체 시스템의 API를 확인해 웹앱이 관리자 계정으로 대신 호출하도록 만들었습니다. 계정 정보는 스크립트 안에만 보관하므로 임직원은 계정 없이 직접 등록하고, 담당자가 요청을 받아 처리하는 과정이 없어졌습니다.

업체 콘솔은 실제 화면에 진행 순서를 표시했고, 웹앱 화면의 개인 코드와 차량번호는 가상 값입니다.

설계할 때 신경 쓴 점

  • 공용 코드 대신 개인 코드공용 코드는 외부로 유출될 수 있다고 판단해, 임직원 246명에게 각각 고유 코드를 부여하고 구글 시트 명단으로 관리하도록 했습니다.
  • 예외 상황 안내정기권 차량, 이미 할인이 적용된 차량, 뒷번호가 같은 차량이 여러 대인 경우를 구분해 안내 문구를 보여 줍니다.
